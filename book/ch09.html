数据快照 2026-09

2025 年，一家全国性财产保险公司的理赔辅助 Agent 进入试点。团队用流行的 Agent 框架搭了一个 ReAct 循环，接上定损查询、案件状态更新、条款检索等十二个工具。演示阶段三条预设流程走得很顺，负责人在立项汇报里写的是"两个月上线"。

试点第三周，两个数字推翻了这个预期。单次理赔任务的工具调用步数，均值是设计值的三倍以上，个别案件超过四十轮；单任务 Token 消耗随之失控，一条处理不下去的案件把当天的预算吃掉一截。更麻烦的是第二次事故：一个工具被误传了案件号，把 A 案件的状态更新写到了 B 案件上，排查用了两天，因为系统只记录了模型输出，没有完整记录每次工具调用的参数与结果。［D｜本书项目复盘，样本 N=2］

复盘会上，团队原来的认知是"Agent 就是在模型外面加个循环"。这次试点证明循环本身一天就能写完，真正决定成败的是循环之外的东西：什么时候必须停下来的判据、工具调用前后的约束与校验、上下文装不下时的取舍、出事之后能不能把整条轨迹回放出来。
